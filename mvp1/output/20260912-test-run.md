## Project: `mvp1` — a minimal, extensible ReAct agent (~1,800 lines, one third-party dep)

The architecture is a **kernel + plug-ins**: `agent/` defines a neutral message model and five interfaces, and imports nothing else from the project. Every other package is an implementation behind one of those interfaces.

### Kernel

| File | Lines | What it does |
|---|---|---|
| `agent/agent.go` | 227 | **The core.** Defines the provider-neutral message model (`Role`, `Message`, `ToolCall`, `ToolSpec`, `Usage`, `Response`) and the five plug-in interfaces: `Provider`, `Tool`, `Memory`, `ContextBuilder`, `Hook` (plus `Hooks` fan-out where the first `BeforeTool` veto wins). Implements `Agent.Run` — the ReAct loop: build context from memory → call LLM → if no tool calls, return final answer → else run all tool calls **concurrently** via `act()` → append observations → repeat until `MaxSteps`. Tool errors, unknown tools, and policy denials become `role: tool, is_error: true` observations so the model can recover instead of crashing. Guards against non-object tool args, and sorts tool specs for a cacheable prompt prefix. |
| `agent/subagent.go` | 30 | Exposes "spawn a fresh agent and run it to completion" as a `Tool`. `Spawn` is a factory, so each delegation gets its own `Memory` — sub-task chatter never pollutes the parent context; the parent sees only the final answer. |

### Wiring

| File | Lines | What it does |
|---|---|---|
| `main.go` | 195 | The only file that knows every concrete implementation. Parses flat JSON config (provider/model, memory, context harness, tool list, MCP servers, approval policy), builds provider → tools → hooks → memory → harness → optional subagent, then runs one-shot (`-q`) or an interactive REPL. Notable: secrets come from env vars only; errors return through `run` rather than `os.Exit` so deferred MCP cleanup executes and doesn't orphan child processes; policy hooks are shared with subagents so delegation can't bypass approval. |

### Providers (`agent.Provider`)

| File | Lines | What it does |
|---|---|---|
| `llm/openai.go` | 139 | OpenAI Chat Completions wire format via raw `net/http` — covers Ollama, vLLM, llama.cpp, LM Studio, OpenAI, Groq, OpenRouter, Together, Mistral. Pure translation, neutral↔wire. Defensively handles sloppy local-model JSON by storing unparseable tool args as a JSON *string* so the transcript still marshals and replays. |
| `llm/anthropic.go` | 112 | Anthropic Messages API via the official Go SDK. Demonstrates a genuinely different wire shape fitting the same interface: system as a top-level field, consecutive tool results buffered and flushed into a single user turn, and `Message.Native` used to replay assistant turns verbatim so thinking blocks/signatures survive across tool-use turns. |

### Tools (`agent.Tool`)

| File | Lines | What it does |
|---|---|---|
| `tool/tool.go` | 40 | `Func` — adapts any Go closure into a tool (the simplest extension path). Plus generic `Args[T]` decoding with model-readable errors, and `Truncate`. |

The most safety-conscious file: shell runs in its own process group with a hard timeout, killed on timeout *and* after exit so `sleep 300 &` can't linger; output capped **while streaming** (runaway printers killed, not buffered); non-zero exit returned as useful info, not a tool failure. | File | Lines | What it does |
|---|---|---|

Appends snapshot-and-write under one lock and use temp-file + atomic rename, so concurrent appends can't persist a stale snapshot and an interrupted write can't truncate the transcript. |

### Tests (5 files, ~360 lines)

- **`agent/agent_test.go`** — drives the loop with a scripted fake LLM: happy-path transcript shape, denied/unknown tools becoming ordered error observations, `ErrMaxSteps`, and a `spy` tool proving non-object args are rejected *before* the tool runs.
- **`tool/builtin_test.go`** — the meatiest suite: shell timeouts killing background children, orphans not outliving the call, output capping while streaming (100 MB test), non-zero exit as observation, and thorough `confine` escape tests (symlinks, `../`, absolute paths, plus a `..rc` dotfile that must *not* be treated as an escape).
- **`tool/mcp_test.go`** — E2E against a real filesystem MCP server (gated on `MCP_E2E=1` + `npx`), plus a crashed-server test asserting calls fail rather than hang.
- **`harness/context_test.go`** — window cuts at user turns; regression test for `MaxMessages <= 0` which used to panic.
- **`memory/memory_test.go`** — 20 concurrent appends all land on disk, reload correctly, and leave no temp files behind.

### Overall impressions

The consistent theme is that **the interesting logic is in failure modes, not happy paths**. The kernel is genuinely small (227 lines) and the five-interface seam is real — each axis (model, capability, persistence, context strategy, policy/observability) is swappable without touching `agent/`. The code is unusually well commented, with `// [agent]` markers explaining *why* rather than *what*, and several comments document bugs that the tests pin down (orphaned pipes, stale snapshots, orphaned tool results, `history[len(history)]` panics).

One note: the `[agent]` comment convention plus `config.json`/`config.anthropic.json` and the compiled 16 MB `minagent` binary suggest this is a teaching/reference implementation rather than a production system — `memory.File` self-describes as "stub-grade" (rewrites the whole file per append), and the MCP client deliberately skips HTTP transports, resources, prompts, and sampling.
