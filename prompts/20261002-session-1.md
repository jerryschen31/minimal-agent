  Concepts

  1. Only the transport changes. Everything after client.Connect(ctx, transport,
  nil) is the same for local and remote servers: session.Tools(),
  session.CallTool(), session.Close(). mcpServer, mcpTool and getMCPTools don't

  ├─────────┼──────────────────────────┼───────────────────────────────────┤
  │ Transpo │ mcp.CommandTransport{Com │ mcp.StreamableClientTransport{End │
  │ rt      │ mand: cmd}               │ point: url, HTTPClient: ...}      │
  ├─────────┼──────────────────────────┼───────────────────────────────────┤
  │ Process │ yes (child, killed on    │                                   │
  │  to     │ close)                   │ no, just HTTP requests            │
  │ manage  │                          │                                   │
  ├─────────┼──────────────────────────┼───────────────────────────────────┤
  │ Auth    │ env vars                 │ headers, e.g. Authorization:      │
  │         │                          │ Bearer ...                        │
  └─────────┴──────────────────────────┴───────────────────────────────────┘

  2. The SDK has no Headers field. I checked v1.8.0, which is the version you
  have. StreamableClientTransport has Endpoint, HTTPClient, MaxRetries,
  DisableStandaloneSSE and OAuthHandler. To send custom headers, you give it an
  *http.Client whose Transport (a RoundTripper) adds them to every request. This
  is the standard Go middleware pattern.

  3. Streamable HTTP. Each client message is an HTTP POST. The server replies
  with either plain JSON or an SSE stream for that one request. By default the
  SDK also opens a long-lived GET stream so the server can push notifications.
  Your agent ignores server pushes, so you could set DisableStandaloneSSE: true.
  Whether that helps depends on the server, and some servers handle the GET
  badly. Start with the default and flip it if you hit trouble.

  4. Trade-off on headers in config. Putting "Authorization": "Bearer sk-..." in
  config.json is simple, but the secret ends up in a file that might get
  committed. The usual fix is to expand ${ENV_VAR} in header values with
  os.ExpandEnv. It's a one-liner and worth doing, but it's optional for this
  slice. OAuth is a separate, later slice (item 5 in your SESSION.md).
  OAuthHandler is the hook for it.

  The http pieces

  http.RoundTripper is a one-method interface: RoundTrip(*http.Request) 
  (*http.Response, error). It turns one request into one response. http.Client
  calls it for every request, so wrapping it lets you change every request in
  one place. Your headerTransport is a wrapper that adds headers, then hands off
  to a base transport that does the real network work.

  http.DefaultTransport is the standard base. It handles connections, TLS,
  proxies and connection pooling.

  Line by line in RoundTrip:
  - req.Clone(req.Context()) makes a copy of the request. The RoundTripper
    contract says you must not modify the caller's request, because the SDK may
    reuse it.
  - req.Header.Set(k, v) replaces any existing value for that header. Add would
    append a second value instead. Set is right for Authorization.
  - h.base.RoundTrip(req) sends the modified copy on. Skipping this call is a
    classic bug, because nothing would ever go out.

  Your pasted version is correct as written.

  http.Client{Transport: ...} is how you plug a RoundTripper in. Don't set
  Client.Timeout. It covers the whole request, including reading the response
  body, so it would cut off a long SSE reply stream. Cancellation already comes
  from ctx.

  The SDK pieces

  These are the same two calls you used for the local server, with a different
  transport:
  - mcp.NewClient(&mcp.Implementation{...}, nil) is identical to the local
    version.
  - &mcp.StreamableClientTransport{Endpoint: ..., HTTPClient: ..., 
    DisableStandaloneSSE: true} is the remote transport, as in DECISIONS.md.
  - mcp.LoggingTransport{Transport: ..., Writer: os.Stderr} wraps any transport,
    so it works here unchanged.

  The functions

  // headerTransport adds fixed headers (e.g. Authorization) to every outgoing 
  request.
  type headerTransport struct {
        base    http.RoundTripper
        headers map[string]string
  }

  func (h *headerTransport) RoundTrip(req *http.Request) (*http.Response, error)
  {
        req = req.Clone(req.Context()) // [agent] a RoundTripper must not mutate the 
  caller's request
        for k, v := range h.headers {
                req.Header.Set(k, v)
        }
        return h.base.RoundTrip(req)
  }

  func connectRemoteMCP(ctx context.Context, name string, config 
  McpServerConfig) (*mcpServer, error) {
        client := mcp.NewClient(&mcp.Implementation{Name: AgentName, Version:
  AgentVersion}, nil)

        // [agent] no http.Client.Timeout: it would also kill long SSE replies. ctx 
  handles cancellation.
        httpClient := &http.Client{
                Transport: &headerTransport{base: http.DefaultTransport, headers:
  config.Headers},
        }

        transport := &mcp.LoggingTransport{
                Transport: &mcp.StreamableClientTransport{
                        Endpoint:             config.URL,
                        HTTPClient:           httpClient,
                        DisableStandaloneSSE: true, // [agent] see DECISIONS.md: no server push needed
                },
                Writer: os.Stderr,
        }

        session, err := client.Connect(ctx, transport, nil)
        if err != nil {
                return nil, fmt.Errorf("failed to connect to MCP server %s: %w", name, err)
        }
        return &mcpServer{name: name, config: config, session: session}, nil
  }

  Bug: LoggingTransport makes DisableStandaloneSSE a no-op

  With DisableStandaloneSSE: false, the no-GET assertion still passed, so I read
  the SDK source. After the initialize handshake, the client calls
  sessionUpdated() on the connection, but only if the connection implements that
  method (client.go:401). LoggingTransport's wrapper (loggingConn) doesn't
  implement it. Comparing requests with and without the wrapper:

  ┌───────────────────────────┬───────────────────────┬────────────────────┐
  │                           │ with LoggingTransport │     without it     │
  │                           │   (your code today)   │                    │
  ├───────────────────────────┼───────────────────────┼────────────────────┤
  │                           │ never opened,         │ opens if the flag  │
  │ Standalone GET stream     │ whatever the flag     │ is false,          │
  │                           │ says                  │ suppressed if true │
  ├───────────────────────────┼───────────────────────┼────────────────────┤
  │ Mcp-Protocol-Version      │ missing               │ 2025-11-25         │
  │ header on later requests  │                       │                    │
  └───────────────────────────┴───────────────────────┴────────────────────┘

  Two consequences:
  - The flag does nothing right now. Your code never opens the GET stream only
    because of the wrapper. If you later remove the wrapper, the flag starts
    working, and that's fine because it's already true.
  - The protocol-version header is missing. The spec says clients must send
    Mcp-Protocol-Version on every request after initialize. Your wrapped client
    doesn't. DeepWiki tolerated it in your smoke test, but a stricter server
    could reject it.

  This only affects the remote path. LoggingTransport is a debugging aid, and
  stdio isn't affected.

  Decision for you

  I haven't changed connectRemoteMCP. These are the options:

  1. Remove LoggingTransport from the remote path (recommended). It restores
     correct headers and makes the flag meaningful. You lose the JSON-RPC debug
     log for remote servers, but you can still see HTTP traffic by wrapping
     headerTransport.base in a logging RoundTripper.
  2. Gate it behind a debug setting, off by default. You keep the log when you
     need it, but you have to remember the debug mode changes behavior.
  3. Leave it as it is and add a code comment saying so. This keeps the missing
     header.

  Once you pick one, I'll make the change. The no-GET and Mcp-Protocol-Version
  assertions will then actually test something, and I'll add them. I'd also add
  a DECISIONS.md entry. It's worth recording that the SDK's wrapper hides
  sessionUpdated.
